## Основные решения

- Адаптивное веб-приложение с двумя интерфейсами: покупатель и сотрудник.
- Модульный монолит, PostgreSQL, фоновые задания из той же кодовой базы.
- Бокс имеет фиксированный состав из конкретных партий. Публикация выделяет остатки под боксы, бронь резервирует готовые боксы, выдача списывает продукты.
- Покупатель задаёт точное время получения внутри окна заведения.
- Продавец отмечает неявку после выбранного времени плюс 15 минут. Автоматической неявки нет.
- Оплата: выбор «на месте» или «онлайн позже». В MVP оба варианта — заглушки, списания денег и платёжного статуса «оплачено» нет.
- История событий и мини-аналитика входят в MVP.

## Технические соглашения

OpenAPI 3.0.3; JSON; UUID; даты RFC 3339 с часовым смещением; сервер хранит UTC, заведение — IANA timezone. Деньги — целые копейки RUB. Временные ограничения проверяет сервер.

Документацию можно опубликовать отдельно от приложения. Инструкции — в разделе публикации. Публикация во внешний аккаунт этим комплектом не выполнена.

Сайт уже собран в site/index.html, API — в docs/api.html. [Результаты проверки](VALIDATION.md). Повторная сборка на Windows: `./build-docs.ps1`, локальный просмотр: `./build-docs.ps1 -Serve` после подготовки окружения по инструкции публикации.
